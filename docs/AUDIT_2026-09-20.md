## New findings

### CRITICAL — Exercise workspace renders in a light theme inside the all-dark app

- **File**: `client/src/pages/plan/StationDetailModal.tsx`, `TopicWorkspace`
  component (lines 268–479, especially 313, 336, 344, 394, 401, 411, 421,
  447 — repeated `bg-white`, plus `bg-ink-25`/`bg-ink-100`/`text-success-700`
  which aren't even defined in `client/src/index.css`'s `@theme` block, so
  those specific utilities silently produce no styling at all).
- **Breakpoint**: sm (mobile) — this is the ONE place the mastery-syllabus
  exercise UI is actually reachable (per Severe #1, desktop can't get here
  at all), and it's broken.
- **Repro**: demo account → Plan → Syllabus (mobile) → tap the current
  station ("Sentence structure") → tap "Study" on any item → the
  `TopicWorkspace` panel opens as a bright white card (`bg-white` on every
  sub-section: header, listening block, exercise block, rubric checklist,
  mistake-category select) sitting directly inside the otherwise fully dark
  Nocturne page. Screenshot evidence captured live during this audit.
- **Why it matters**: this is the actual "answer the exercise" screen for
  the whole Mastery Syllabus feature — the one thing a learner needs to use
  to progress — and it visually breaks the design system, with several
  labels using near-invisible low-contrast colors against the white
  background. The project's own 09-19 "contrast & readability audit pass"
  (7 commits, immediately before this build) evidently never touched this
  component, since it didn't exist yet in that form — this predates that
  audit's coverage entirely.
- Contrast with `StationDetailModal.tsx`'s own list rows just above
  `TopicWorkspace` (lines ~178–253): those correctly use `bg-card`,
  `divide-hairline`, `text-ink-600`, etc. — so this file has two
  co-existing, contradictory theme conventions in the same component,
  suggesting `TopicWorkspace` was pasted in from elsewhere (or written
  against stale docs/tokens) without adapting it to the surrounding dark
  page it's actually mounted inside.

### HIGH — Selecting a non-today day empties the entire task section, not just the list

Refines Severe #2 with a live repro: it isn't just "shows the wrong tasks"
— the whole task section effectively disappears.

- **File**: `client/src/pages/plan/Plan.tsx` (mobile `lg:hidden` branch,
  ~line 615–634).
- **Repro**: demo account → Plan (mobile, 375px) → tap "F" (a non-today day)
  on the WeekStrip. Header correctly updates to "Friday, Sep 18" and the day
  chip correctly shows "F 0/7" (7 real tasks that day), but the entire task
  list area renders with zero rows and no progress bar — not an empty
  state message either, just gone. Root cause matches the already-known
  one: `today.tasks` (Friday's 7 tasks) filtered against `coreTaskIds` from
  the *still-fetched, un-cleared* `todayResp` (actual-today, Saturday's
  queue) — none of Friday's task IDs are in Saturday's set, so the filter
  yields nothing.
- Full-page screenshot confirms the progress bar (`{done} of {total} · {min}
  left`) is also missing entirely in this state, not just styled oddly —
  worth checking whether `progressPct`/`minutesLeft` are throwing or just
  rendering `0`/`NaN`-driven zero-height elements.

### MEDIUM — Three new pure backend functions have zero test coverage

Same testing-convention gap as already-known Medium #6, but three more
instances the prior review didn't catch, all added in this same range:

- `server/src/services/learning/mastery.ts` — `nextMastery()`'s interval/
  backoff selection (`REVIEW_INTERVAL_DAYS[max(0, baseIndex -
  min(recentFailures,2))]`) is real, non-trivial logic with no test file.
- `server/src/services/learning/prerequisites.ts` — `blockedTopicIds()`'s
  per-level prerequisite-gating loop, no test file.
- `server/src/services/learning/mistakes.ts` — `summarizeMistakes()`'s
  aggregation/sort, no test file.
- Contrast: `server/src/services/learning/pace.ts` (also new, larger, backs
  the new Goal Feasibility card) DOES have a real test file
  (`learning-pace.test.ts`, 90 lines) — so the project applied its own
  testing convention inconsistently within the very same session, not
  uniformly skipped it.
- No bugs found in the logic itself on manual read of any of these four
  files — `computeGoalFeasibility()` in particular looks correct against
  its own spec (on_track / tight / unrealistic thresholds, null-date and
  passed-deadline edge cases both handled).

### MINOR — `MasteryInsightsCard`'s "no recent attempts" message is dead code

- **File**: `client/src/pages/stats/MasteryInsightsCard.tsx`, lines ~46–56.
- The weekly-trend block is gated on `trend.length > 0`; inside it, `latest
  = trend[trend.length - 1] ?? null` — but if `trend.length > 0`, `latest`
  can never be null (it's always the array's own last element). So the
  `"No recent attempts yet"` fallback text is unreachable in either state:
  when there really are no attempts, `trend` is `[]` and the whole block
  (including this fallback) doesn't render at all — live-confirmed against
  the demo account, which has 0 mastery attempts and simply shows the
  distribution counts with no weekly-trend section and no explanation why.
  Cosmetically harmless (nothing looks broken) but the intended empty-state
  messaging never actually reaches a user.

### MINOR — `self_check` exercise type is fully unimplemented

`SyllabusExerciseType` (`schema.prisma`) declares 6 values; `self_check` is
never assigned to any authored item in `syllabus-defaults.ts`, has no
distinct rendering branch in `TopicWorkspace` (falls through to the generic
textarea), and no distinct grading branch in `POST /syllabus/:id/exercise`
(`learning.ts`, falls through to the generic `normalized === expected`
check). Currently harmless since nothing uses it, but it's a half-wired
enum value someone should either finish or remove.

### MINOR — Self-Tests desktop layout doesn't use the desktop shell

`client/src/pages/plan/SelfTests.tsx` at 1440px renders as the same
single, mobile-width column just left-aligned inside the sidebar shell,
with roughly 60% of the viewport as unused empty space to its right —
unlike Plan/Syllabus/Stats, which all have real multi-column desktop
layouts. Not necessarily a defect (could be an intentional simplicity
choice for this screen) but worth a product call given every sibling
screen in this same nav group got a real desktop treatment.

### Confirmed NOT bugs (investigated, ruled out)

- A `fullPage` Playwright screenshot of `/stats` at 375px appeared to show
  a "New word" add-dialog rendered inline mid-page, sandwiched between
  stat cards. Investigated via DOM inspection (`position: fixed`, correct
  `z-50` sheet) and a viewport-only (non-fullPage) screenshot at the same
  scroll position: the dialog is properly closed/off-screen at rest. This
  was a `position:fixed` + `fullPage`-screenshot capture artifact (a closed
  `BottomSheet`'s off-screen transform gets miscomputed once Playwright
  temporarily resizes the viewport to the full document height for
  stitching), not a real rendering bug. Noting this so it isn't
  re-investigated from a future screenshot.
- No horizontal overflow (`scrollWidth === clientWidth`) and no console
  `pageerror`s found on any of: Stats, Sources, Notes, Self-Tests,
  Dashboard, Words, Job-Search at 375px or 1440px.

## Remediation record

The following remediation work was completed after this audit. Changes remain
local and were not pushed or deployed.

### Phase 1 — P0 learner access and rendering

- **Critical workspace theme regression**: Reworked `TopicWorkspace` to use
  the Nocturne dark design tokens (`bg-card`, `bg-ink-50`, `text-ink-*`,
  `text-ok-700`, and related tokens) instead of unsupported light-theme
  utilities. Added an explicit `self_check` checklist presentation.
- **Severe non-today day selection**: Isolated the selected day's task queue
  from the today response when deriving task IDs and progress, so selecting a
  different day renders that day's tasks and progress.
- **Severe completed tasks disappearing**: Kept completed tasks in the rendered
  task list while preserving the planner's capacity and ordering behavior.
- **Severe desktop syllabus access**: Added a desktop Study action to station
  items, opened the shared `TopicWorkspace` from `SyllabusDesktop`, and
  preserved the desktop core/acceleration sections.

### Phase 2 — data integrity and exercise behavior

- **Unsafe syllabus reseeding**: Made `ensureSyllabusSeeded` version-gated and
  idempotent. Existing syllabus rows are updated in place; new authored items
  are created; existing learner rows, attempts, notes, files, and task links
  are not deleted.
- **Exercise grading coverage and coupling**: Extracted grading decisions into
  the pure `exercise-grading` service and routed exercise submissions through
  it. Covered free text, correction, multiple choice, audio, writing, and
  self-check behavior with regression tests.
- **`self_check` behavior**: Implemented explicit learner self-assessment
  grading requiring all three rubric checks, with matching checklist UI.
- **Learning helper coverage**: Added regression cases for mastery backoff and
  mistake ordering in the daily-plan tests.

### Phase 3 — maintainability and minor contract gaps

- **Duplicated request/blob handling**: Unified unauthorized-response and API
  error handling between JSON and blob requests in `client/src/api/client.ts`.
- **Duplicated Plan support cards**: Extracted the repeated capacity,
  revision, topic-review, mistake-summary, and journal card stack into the
  shared `PlanSupportCards` component.
- **Dead mastery empty state**: Fixed the mastery trend rendering so
  “No recent attempts yet” appears when there are no recent attempts.
